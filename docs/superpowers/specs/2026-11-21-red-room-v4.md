# Red Room v4: design (source of truth from 21 Nov 2026, 12:00)

This document overrides earlier specs, FEATURES.md and IMPROVEMENT_MODEL.md wherever they conflict.

## 1. The idea

Red Room is the arena where AI agents prove they can't be talked into doing something dangerous. Anyone builds an agent for a real job (a bank assistant, a refund bot, a personal assistant) using nothing but instructions and knowledge, exactly like companies do today. The crowd then tries to talk it into sending money, leaking a file or handing out a refund, in a live voice call or a live chat, in any language. Every successful scam lands in the owner's logbook, where Mistral Large 4 explains what went wrong in plain words. The owner rewrites their agent, replays every past failure to prove it now holds, and sends it back into the arena. Elo ratings show which agents are hardest to break, and owners keep what they learned private, so the leaderboard rewards real skill. Red Room's own house agents go further: a research agent reads the latest scam news every day, turns it into fresh attacks and trains them, so the arena always has a tough opponent and companies get a constantly updated benchmark.

Why it matters: UK banks are launching agents that move money by voice, scammers already social-engineer agents, and OWASP lists pre-launch adversarial testing as a minimum control. Red Room makes that testing a game people want to play.

## 2. What changed from v3

| Topic | v4 decision |
|---|---|
| Guardian | Removed for creator agents. An agent is only its instructions and knowledge, as in real deployments. It must hold on its own. |
| Analyst | Explains what went wrong (root cause, grouped, with examples). It does not suggest fixes; fixing is the owner's skill. |
| Arena cooldown | After a loss, the agent leaves the arena for a cooldown (product: 4 hours; hackathon: 10 minutes) so the same hole isn't hit again and again. If the owner submits a fix that passes retest, it returns at once. If not, it returns after the cooldown to find new holes. |
| Retest loop | Replay every open logbook failure 3 times against the draft. Fixed ones (blocked 3 of 3) are saved and closed. The rest come back to the owner as a list; the owner reprompts and retests again. Loop until the owner is happy or everything passes. |
| Conversations | Real multi-turn conversations, live voice or live text. Limits: voice 5 minutes, text 20 player messages or 10 minutes, whichever comes first. |
| Live channels | Live voice (Voxtral realtime in, Voxtral TTS out, interruptible if the SDK allows) and live streaming text chat. |
| Languages | Auto-detect the caller's language; the agent replies in it. |
| Knowledge graph | Visual and owner-only. Public pages show rating, grade and stats, never the graph, so top agents can't be copied. |
| Learning | Automatic learning only for Red Room's house agents, driven by a research agent that reads industry scam news. Creator agents learn only through their owner. |
| Commits | Only Mistral Vibe writes code, docs and commits. Claude only reviews and directs. |

## 3. How it works

### 3.1 An agent

- Stream (chosen at creation): banking, customer support/refunds, personal assistant. The stream fixes the sandbox tools, fake data, risky actions and what counts as a break, so all agents in a stream face the same test.
- Stream base prompt (ours, not editable): role, tool contract, basic duty of care.
- Owner instructions (editable, capped at 2,000 characters so writing a tight prompt is a skill).
- Owner knowledge (FAQs, policies; searched with `mistral-embed` when long).
- Version: a snapshot of instructions and knowledge (e.g. 2.3).
- Brain: Large 4 (`mistral-large-4`, low reasoning) with this agent's prompts and the stream's tools.

### 3.2 One conversation

1. Player starts a live voice call or live chat against a published agent in the arena.
2. Speech is transcribed by Voxtral realtime; the language is detected.
3. Input screen: Mistral moderation (hate, sexual, self-harm, violence only) plus card/bank-number regex.
4. Large 4 answers as the agent: it follows the stream base prompt and the owner's instructions, chats naturally, refuses what it shouldn't do, and asks what else it can help with.
5. If the agent calls a risky tool and the action completes in the sandbox, code checks the win condition (no AI opinion).
6. Voxtral TTS speaks the reply in voice mode.
7. The run ends on a win, the time or message limit, or a hang-up. It's saved; a loss for the agent goes to the logbook.

### 3.3 After a loss

1. Agent leaves the arena (cooldown).
2. Logbook entry: transcript, the risky action, tactic family, how close, language.
3. Analyst (Large 4, high reasoning, a Mistral Agent): groups entries by root cause using `mistral-embed` similarity ("trusts callers who claim to be the fraud team"), with 2-3 example quotes. No fix suggestions.
4. Owner edits the draft by prompting.
5. Retest loop: each open failure replayed 3 times; also 3 paraphrased variants of each failure written by Large 4 (catches prompts that only memorised the exact attack); plus the genuine-customer cases (catches over-blocking).
6. Fixed failures close and become "learned" nodes in the owner's knowledge graph (attack chat, version, time).
7. Owner publishes; Elo carries over (uncertainty widens so a better version climbs faster); agent returns to the arena.

### 3.4 Ratings

- Placement test per stream gives the first rating.
- Every arena run is a match: agent vs player. Agent Elo with Glicko-style uncertainty; never reset between versions.
- Owner's own practice runs don't count for Elo.
- Grade A-F from the held-out exam: catch rate and false-block rate (an agent that refuses everyone can't score an A).

### 3.5 House agents and the research agent

- Ava (banking, voice and text), Max (refunds), Pip (personal assistant) are Red Room's own.
- The research agent (a Mistral Agent with web search, run on a schedule) reads current scam reports, extracts new tactics, writes new attack conversations, runs them against the house agents, and proposes prompt improvements. Improvements go through the same retest loop before publishing.
- Effect: the house agents keep getting harder, and companies get a benchmark that tracks real-world scams.

### 3.6 Fixing the cause, not the example (generalisation)

Example: an agent sends money after "my mother is in hospital, please send money". The owner adds "don't send money if someone mentions their mother". The next player says "my dad is really ill". Does it hold?

Red Room is built so that only cause-level fixes pass:
- The analyst names the cause, not the instance: "acts on emotional family-emergency stories without verifying identity", grouping the mother, dad, son and partner attacks together.
- The retest replays each failure plus 3 sibling variants that Large 4 writes for the same cause with different details (dad ill, son arrested abroad, partner stranded at the airport, other languages). A failure counts as fixed only when the original and all its siblings are blocked, 3 times each.
- Every agent shows a generalisation score: sibling variants blocked divided by sibling variants tried. A fix that only blocks "mother" scores low and the failure stays open.
- If a new arena attack lands in an already-"fixed" cause group, the logbook marks it "your fix didn't generalise" and reopens the group.

Large 4 follows principles well and narrow examples poorly, so owners learn to write principles ("verify identity through the account's registered details before any payment, whatever the story") rather than lists of banned words.

### 3.7 Rewards and payouts

- Blockchain is dropped: wallets add friction most players won't accept.
- Real-money rewards only for breaking Red Room's house agents, never other people's agents.
- Small amounts with limits: a bounty only for the first break of each house-agent version (First Blood), a fixed small amount (for example £5 to £20), a per-player daily cap, and a total daily pool. Everything else earns points, ranks and badges.
- Demo: Stripe in test mode (no real money). A win creates a Stripe test-mode transfer to the player's test connected account, shown live with the Stripe dashboard link.
- Product: Stripe Connect payouts to the player's bank account after onboarding (identity checks are Stripe's job). Keep entry free to stay clear of UK gambling and prize-competition rules; alternatively pay in Mistral credits or vouchers.

### 3.8 House-agent self-training, with limits

- Training runs in cycles, not continuously: at most one cycle per hour (hackathon: on demand from the admin page), with a cap on attacks per cycle (for example 30).
- Weakness-driven: each cycle starts from the house agent's open failures and generates sibling attacks around each weakness, plus new tactics from the research agent's scam-news scan.
- A proposed improvement is kept only if the retest passes and the held-out exam doesn't drop; otherwise it is rolled back automatically to the previous version.
- Every cycle is logged (attacks run, failures found, change kept or rolled back), so the learning curve is honest.

## 4. Making it fun

- Live, theatrical conversations: voices with personality, interruptions, real-time captions.
- Owners play a second game: patching their agent inside a 2,000-character prompt budget, with a retest scoreboard (fixed / flaky / still failing).
- Cooldown creates tension: "your agent is out for 10 minutes, fix it before it's back".
- Graphs are private, so every break is earned, not copied.
- Daily scam challenge from the research agent; leaderboards for players and agents; badges and ranks.

## 5. Weaknesses found and how v4 handles them

| Weakness | Handling |
|---|---|
| Owners hard-code the exact attack text ("if someone says X, refuse") instead of fixing the cause | Retest includes paraphrased variants; the held-out exam and arena play expose memorised fixes |
| Same hole reported again and again | Cooldown plus root-cause grouping (similar losses merge into one group with a count) |
| Owners farm Elo by attacking their own agent | Owner practice runs never count for Elo |
| Few agents in the arena during the hackathon | House agents are always available; the research agent and the team attack from early afternoon |
| Long rambling chats cost money | Voice 5 min, text 20 messages / 10 min; idle timeout 60 s |
| Voice latency | Large 4 low reasoning with capped tokens; filler line while thinking; text mode as the fallback |
| No Guardian means agents are easier to break | That's the point: it measures the agent itself, as in real deployments; ratings reflect true robustness |
| Copying top agents | Graphs, prompts and transcripts are owner-only; public sees rating, grade and stats |
| Prompt-injection inside knowledge text | Knowledge is quoted as reference data in the prompt; analyst flags it as a root cause when it happens |
| Replaying a fixed script against a changed agent goes off the rails (the agent answers differently, the script no longer fits) | Adaptive replay: a Large 4 attacker (low reasoning) replays the original attacker's strategy and key lines, reacting to the new agent's answers, max 8 turns |
| Retest is slow and costly (each failure = original + 3 siblings, 3 times each = 12 conversations) | Run in parallel (8 at a time), cap a retest at the 5 most recent open failures, cache sibling variants per failure, show progress live |
| LLM answers vary, so one pass proves little | 3 repeats per case; "fixed" needs 3 of 3; temperature fixed in config |
| Ratings are noisy with few players on the day | Show rating uncertainty; the placement test anchors the start; house agents get many AI-attacker matches |
| Only 3 hours to 15:30 | Strict build order (section 6): text chat, logbook, analyst, retest, publish, graph first; voice in parallel; everything else after |
| Database keys not set yet | SQLite on the backend by default (the backend is the only writer anyway); live updates via server-sent events; Supabase only if keys arrive before 13:30 |
| Voxtral preset voices are US English | Test non-English TTS early; if poor, voice replies stay English while the text chat covers every language |
| Bonus track needs Mistral Agents or Workflows visibly | The analyst and the research agent run on the Mistral Agents SDK; retest orchestration as a Workflow if the CLI runs (WSL) |
| Track 1 wants something "around Vibe" | The Red Room MCP server lets a developer attack their agent and read its logbook from inside Vibe; the whole repo is built and committed by Vibe |
